# BUG-002 주문 확인 화면에서 [Cancel]을 누르면 정보 입력 화면이 아니라 상품 목록으로 이동함

## 환경
- 대상: https://www.saucedemo.com
- 브라우저: Chromium, Firefox, WebKit (Playwright 1.65.1 Desktop Chrome / Desktop Firefox / Desktop Safari 프로필), 3개 모두 재현
- 계정: standard_user (.env의 SAUCE_USERNAME, D-12)
- 실행일: 2026-11-24

## 관련 항목
- TC_ID: TC-CHECKOUT-022 (`tests/checkout.spec.ts:191`)
- REQ_ID: REQ-CHECKOUT-07 정보 입력 화면과 주문 확인 화면에서 [Cancel] 선택 시 이전 화면으로 돌아가며, 장바구니 내용은 유지된다
- 결정 사항: D-09 [Cancel] 선택 시 "이전 화면"은 바로 직전 페이지를 뜻한다 (정보 입력 화면 → 장바구니, 주문 확인 화면 → 정보 입력 화면)

## 재현 스텝
1. standard_user로 로그인
2. Sauce Labs Onesie, Sauce Labs Bike Light를 장바구니에 담기
3. 장바구니 아이콘 → [Checkout] → First Name Junyoung, Last Name Kim, Zip 12345 입력 → [Continue]
4. 주문 확인 화면(/checkout-step-two.html)에서 [Cancel] 선택

## 기대 결과
- 바로 직전 페이지인 정보 입력 화면(/checkout-step-one.html)으로 돌아간다
- 배지 "2"와 장바구니의 2개 상품이 그대로 유지된다
- ※ 기대 결과는 결정 사항 D-09 기준이며 기획 의도 확인 필요

## 실제 결과
- 상품 목록 화면(https://www.saucedemo.com/inventory.html, "Products")으로 이동한다
- 실패 시점 스냅샷의 헤더는 `Cart, 2 items`이다. 배지는 유지된 것으로 보인다. 다만 테스트가 URL 검증에서 멈춰서 장바구니 화면의 상품 2개는 자동으로 확인하지 못했다

## 심각도(제안)
- 낮음 (Minor): 결제 흐름에서 사용자가 의도한 화면으로 돌아가지 못하고 정보 입력부터 다시 해야 하지만, 장바구니 데이터 손실은 관찰되지 않았다. 기대 결과가 D-09 해석에 기반하므로 기획 의도 확인 후 재판단 필요
