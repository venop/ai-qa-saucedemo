# 관찰 사항

제품 버그로 확정하지는 않았지만 기록해 둘 현상을 적는다. 버그로 판단되면 별도 버그 리포트로 옮긴다.

---

## OBS-001 결제 정보 입력 화면 진입 직후 입력값이 사라지는 현상

| 항목 | 내용 |
|---|---|
| 상태 | 관찰 중 (제품 버그로 판단하지 않음) |
| 최초 관찰 | 2026-11-23, 3단계 결제 자동화 테스트 작성 중 |
| 화면 | 정보 입력 화면 `/checkout-step-one.html` |
| 브라우저 | webkit (Playwright `Desktop Safari`)에서만 관찰됨 |
| 빈도 | 병렬 실행 시 16회 중 2회 실패 (재시도 처리 전) |
| 영향 TC | TC-CHECKOUT-003, 009, 011, 017 (정보 입력을 거치는 결제 TC 전부) |

### 현상
장바구니에서 [Checkout]을 눌러 정보 입력 화면으로 들어간 직후 First Name, Last Name, Zip/Postal Code를 차례로 입력하면, 먼저 입력한 값이 가끔 지워진다.
- 예: First Name은 비어 있고 Last Name `Kim`, Zip `12345`는 남아 있다.
- 그 상태로 [Continue]를 누르면 "Error: First Name is required"가 나오고 다음 단계로 넘어가지 않는다. 그래서 TC가 실패했다.

### 재현 조건
```
npx playwright test tests/checkout.spec.ts --project=webkit --repeat-each=4 --workers=8
```
- 결제 TC 4개 × 4회 = 16회를 webkit에서 worker 8개로 병렬 실행한다.
- 재시도 처리 전에는 이 조건에서 16회 중 2회 실패했다. 세 브라우저를 함께 돌렸을 때는 webkit 결제 TC가 3번 중 2번 실패했다.
- 실패한 테스트의 trace(`--trace=retain-on-failure`)에서 입력 직후 첫 필드 값이 비어 있는 것을 확인했다.

### 판단 근거 (테스트 쪽 타이밍 문제로 판단)
1. **병렬 실행에서만 나타남:** 같은 TC 하나만 webkit에서 돌리면 5회 모두 통과했다. 실패는 여러 테스트를 동시에 돌려 부하가 걸릴 때만 나왔다.
2. **webkit에서만 나타남:** 같은 조건에서 chromium, firefox는 실패하지 않았다.
3. **사람은 겪기 어려운 시점:** 화면이 뜬 뒤 몇 밀리초 안에 자동으로 입력할 때 생긴다. 화면이 그려지는 중에 입력 필드가 초기화되면서 먼저 넣은 값이 지워지는 것으로 추정한다. 사람이 입력하는 속도로는 재현되지 않았다.
4. **입력이 반영된 뒤의 동작은 정상:** 세 값이 모두 들어간 상태에서는 다음 화면 이동, 상품 표시, 금액 계산 등 모든 검증이 통과했다.

추정 원인은 확인하지 않았다(사이트 소스는 분석하지 않음). 실제 Safari에서 사람이 입력할 때도 값이 지워지는 사례가 나오면 제품 버그로 다시 판단한다.

### 테스트에서의 처리
- **위치:** `pages/CheckoutPage.ts`의 `fillInfo()`
- **방식:** 세 값을 입력한 뒤 각 필드 값이 입력값과 같은지 확인하고, 다르면 세 값을 처음부터 다시 입력한다. 고정 대기(waitForTimeout) 없이 `expect(...).toPass({ timeout: 10_000 })`로 재시도한다.
- **검증 내용은 바꾸지 않음:** 테스트 파일의 assertion(에러 문구, URL, 상품, 금액 등)은 그대로다. 재시도는 입력 동작을 안정화할 뿐이고, 10초 안에 값이 반영되지 않으면 테스트는 실패한다.
- **기록:** 재입력이 일어나면 test annotation `입력값 재입력 발생`(예: "CheckoutPage.fillInfo: 총 2회 입력 (재입력 1회)")을 남긴다. HTML 리포트의 각 테스트 상세 화면에서 볼 수 있어, 이 현상이 얼마나 자주 나는지 계속 확인할 수 있다.

### 처리 후 확인
| 날짜 | 조건 | 결과 | 재입력 발생 |
|---|---|---|---|
| 2026-11-23 | webkit, `--repeat-each=4 --workers=8`, 3회 | 48/48 통과 | (기록 기능 없음) |
| 2026-11-24 | webkit, `--repeat-each=4 --workers=8`, 1회 | 16/16 통과 | 0회 |
| 2026-11-24 | webkit, `--repeat-each=8 --workers=8`, 3회 | 96/96 통과 | 7회 (모두 1회 재입력 후 통과) |

재입력 7회는 TC-CHECKOUT-003, 009, 011, 017에서 고르게 나왔다. 특정 TC의 문제가 아니라 정보 입력 화면 진입 시점의 문제라는 판단과 맞는다.
