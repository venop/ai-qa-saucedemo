# BUG-003 입력 필드에 공백만 입력해도 검증을 통과함

## 환경
- 대상: https://www.saucedemo.com
- 자동화: Chromium, Firefox, WebKit (Playwright 1.65.1 Desktop Chrome / Desktop Firefox / Desktop Safari 프로필), 3개 모두 재현
- 수동 재현: Chrome, standard_user (검토자 직접 재현, Zip/Postal Code)
- 계정: standard_user (.env의 SAUCE_USERNAME, D-12)
- 실행일: 2026-11-24

## 관련 항목
- TC_ID:
  - TC-CHECKOUT-029 First Name (`tests/checkout.spec.ts:219`)
  - TC-CHECKOUT-030 Last Name (`tests/checkout.spec.ts:237`)
  - TC-CHECKOUT-025 Zip/Postal Code (`tests/checkout.spec.ts:140`)
- REQ_ID: REQ-CHECKOUT-02 필수 정보를 비운 채 [Continue] 선택 시 비어 있는 항목의 에러 메시지를 표시하고 다음 단계로 이동하지 않는다
- 결정 사항: D-08 First Name, Last Name, Zip/Postal Code에 공백만 입력한 경우 빈 값으로 처리한다 (Q-02에서 공백만 입력은 D-08로 결정)

## 재현 스텝
공통 사전조건:
1. standard_user로 로그인
2. Sauce Labs Onesie를 장바구니에 담기
3. 장바구니 아이콘 → [Checkout]으로 정보 입력 화면(/checkout-step-one.html) 진입

| 케이스 | First Name | Last Name | Zip/Postal Code | 이후 |
|---|---|---|---|---|
| A. First Name (TC-CHECKOUT-029) | 공백 3칸 | Kim | 12345 | [Continue] 선택 |
| B. Last Name (TC-CHECKOUT-030) | Junyoung | 공백 3칸 | 12345 | [Continue] 선택 |
| C. Zip/Postal Code (TC-CHECKOUT-025) | Junyoung | Kim | 공백 3칸 | [Continue] 선택 |

## 기대 결과
- 공백만 입력한 값은 빈 값으로 처리되어 해당 필드의 에러가 표시된다
  - A: `Error: First Name is required`
  - B: `Error: Last Name is required`
  - C: `Error: Postal Code is required`
- 정보 입력 화면(/checkout-step-one.html)에 머무른다

## 실제 결과
- 세 케이스 모두 [Continue] 선택 후 에러가 표시되지 않는다 (`getByTestId('error')` 요소 없음)
- 세 케이스 모두 주문 확인 화면("Checkout: Overview", /checkout-step-two.html)으로 이동한다. Item total $7.99, Tax $0.64, Total $8.63이 표시되고 [Finish]도 누를 수 있다
- 자동화 테스트에서 공백 3칸이 실제로 입력된 것을 확인함 (`toHaveValue('   ')` 통과). 입력 실패가 아니라 검증 통과다
- 수동 재현에서 Zip에 공백 2칸으로도 재현됨 (검토자 확인)

## 원인 (추정)
- 세 필드가 같은 방식으로 실패한다. 그래서 입력값의 앞뒤 공백을 제거하지 않고 "빈 문자열인지"만 검사하는 공통 검증 로직 때문으로 추정한다
- 화면 동작만 보고 한 추정이다. 제품 코드로 확인하지 않았다

## 심각도(제안)
- 중간 (Major): 필수 정보 검증을 우회해서 이름·성·우편번호 없이 주문을 진행할 수 있다
